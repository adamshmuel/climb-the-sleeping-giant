# Making a ruling

## Evidence first
- A fact the world can answer is measured in one read-only Studio call before two rulings are weighed.
- On how a job measured something: read the job's own lines that take the measure (start, peak, bar) first.
- On a Play result: read the run's printed result lines, not a summary of them.
- Before using a test result as evidence, check its setup matches a real player's (for example, the rescue's last safe spot).
- Before quoting an owner's decision, search `work/` and `docs/` for later rulings on the same thing and quote the newest.
- When the timing makes the result certain, decide from the numbers. Don't spend a Play run on it.

## Trials
- Before a trial, list each possible result and the pick it leads to. Cut any case that can't change the pick.
- Before chasing "every try works", name what the player needs when it fails, and price that safety net first.

## Limits
- Write the bar the player feels ("never thuds", "can see and grab the item"), not a stand-in (a gap size, a count). Measure any stand-in against that bar, on the measured shape, before anything is built to it.
- Every reach limit names what it guards ("a new way in from outside") and which spots count, above and below.
- A ruling that asks for a check writes the rule to check by: how high, how far, from which spots. The check follows each spot it finds: where it leads, and whether players reach it today.
- Before a stop rule sends work back, check each failing limit is one a player feels. If not, lower it and let Play decide.

## Fixes and placement
- A ruling that offers fix paths says what each must leave untouched (the core path, a route, a ladder end).
- A ruling on where a way up goes starts with a table: what sits at the top, and which players need it. Then the route.
- When a part on a main character is questioned, also question the gameplay spots that pull players there. Moving one spot can remove a whole path.
- How to measure, place and fix the parts themselves: `world-parts` skill.

## Fairness
- Name where the routes join. Anything past that point gets its own left-against-right check.
- Judge a one-sided route on the trip there and the trip home.
- When a table lists one side of a mirrored world, count both sides before judging.

## Proofs and review plans
- Split spots by the idea's "What matters most": play every core spot, sample the rest (for example, the steepest spot per 4-stud square). Pick the sample rule before Play if the count is large.
- Tries match value: one try where players can't normally go, 3 of 3 where they can. A proof too big for one task is split when the plan is written.
- Every whole-session proof includes the core action after a real respawn.
- A review plan gives the first-minute play its own small budget. The must-shows get their own part, starting from a placed spot.
- A phone part holds at most about 3 checks, and saves all its shots with one copy at the end.
