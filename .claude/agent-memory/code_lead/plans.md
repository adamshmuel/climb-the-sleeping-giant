# Plans

- A plan that changes a shared check (a reach, a limit) lists the tests that place things by it as "setup moves, expectations stay".
- A move right after the engine spawns a body: measure it in Play first (position and who runs its physics, every frame for 1 s), then fix. If the task can't hold that, it goes to a later spec.
- A rule that changes what happens after a climb names the parts it covers ("the two cap ties"), and the code checks those parts, not only the body zones.
- Before writing a new world script number into a plan, list `tools/world/` and the other plans' script names.
- At a task close, its review, result and close notes go to `docs/progress/v2/history/<plan-part>.md` under `## Task N`; the plan keeps rulings plus a one-line `- History: [..](..#task-n)` link. Never make a bold task line a heading (job-check reads headings).
- A ruling's "Stands on" list for a grace or skip in the target picker misses the show slam and director tasks it also reads (plan 6 Tasks 4, 8): grep the plan for every task touching the same function before copying the list.
- A job that runs a spec's body in Edit with a Jest stub (to read rows the fetch cuts) is budgeted as the spec's length plus 40 lines and 14 calls (6a2 broke job-check's 300 lines and went 2 calls over, 2026-11-04).
- A part placed by an earlier task to hide a pocket (R-141 bush, stuck safety Task 48) can show as a sink row: grep tools/world for its position before planning a move (5b, 2026-11-04).
- A move that shifts a ladder's top also shifts every spec rule measured from that end (5b2: Rule 37's nest distance went 3.9 to 5.5): grep the spec and tests for distances from the moved end before writing the card (2026-11-04).
- A "decided" re-fit in a ruling is not "built": before writing a card that stands on art, read the art in Edit (one call). p5t13b: designer's strap re-fit was priced, not built (2026-11-08).
- Before writing a card from a plan's Files line, check each file exists and each "change" is still needed: p5 Task 14 named `WalkMap.spec.luau` (made later by plan 3 Task 9; the real map is in `StuckScan/OnTheGiant.spec.luau`) and a PathCheck area change already met (x ±68.8 measured), 2026-11-08.
- A jump or reach check never takes a named list of jump surfaces alone: add every body surface walkable from them (walk flood), and rays see every solid part (p5t15 crease from the boot tops, 2026-11-08).
- Before a card names a world part from an old world script, grep the tests for "does not ask for <name>": `RightBoots_Walk` was removed in stuck-safety Task 24, yet 03-climb and WalkHelpers still name it (p5t15d, 2026-11-09).
- Check a coordinator's count against the spec before the card: "12 landing spots" was 10 by Rule 43 (side ladders dropped 2026-11-03), p3t8, 2026-11-10.
- A route card checks a later task's trail-end test (Task 13's 30° run-in) against the walk-time test before placing points: one straight approach broke test 2b's 0.3 s; two 25° approaches passed on paper (p3t8c, 2026-11-10).
- Before a card says a world script's rerun will print "already done", check that its hand points still stand on built parts (p3t8a: 08-route's Belly_* points sat on ramps removed in Tasks 5 and 6b, so the script couldn't run), 2026-11-10.
- A card that adds many route points runs the walk check on every planned link in its measure step, lists all problems, and prices the fix step from that list. A check that stops at its first failure made each fix one dry run: 8c carded 2 spares and used 169 calls (p3t8c, 2026-11-10). Each table F stop row gets a call cap.
- A code task's "Stands on: the spec" misses other plans' tasks that make the types it extends. Before carding, read the current module (types, enums) for every name the task uses: p5 Task 1 sets Epic/Legendary slots, but those ranks come from plan 4 Task 1, not built (2026-11-10).
- Widening a list (`RarityOrder`) also widens every loop over it that reads the world: grep each `for ... in <list>` first. p4t1: `readEggTemplates` would have asked for Epic/Legendary eggs not built yet and broken the server start; the card pins it to 3 names until plan 4 Task 2 (2026-11-10).
- When a card adds names to a list or config, grep the tests for each new name used as a wrong value ("not a rank" examples) and list the hits on the card. p4t1: PlayerInfo.spec used "Legendary" as the invalid rank and turned red. Also grep `src/` for the new numbers already written by hand, and fold those copies in (p5t1: WalkAreaCheck held 65, 0.7, 0.2, 1), 2026-11-10.
- Before naming the next task from a handoff's order ("then Task 12"), read that task's Files and test lines for pieces another task makes: p5 Task 12 removes Task 7's bare-spot allowance and extends Task 8's script 21, but its Stands on said only Tasks 1 to 3 (fixed to 1 to 8, 2026-11-10).
- A "lost item returns" rule needs a take counter per slot: "countdown still running" alone lets a stale egg come back after its slot refilled and was taken again (p5t5 card, 2026-11-10).
- Card titles: `job-check` reads egg/nest + "goes back"/"place"/"build" in a heading as world placing and asks for a reach walk. Say "returns" in code-only titles. A heading that names another Task needs its own Stands on line.
- A card's `script_grep` sync check names a query only the changed file holds (a new describe title, "function EggSlots.setLocked"), never a common name: "returnEgg" hit the 50-match cap (p5t5 builder, 2026-11-10).
- Before carding a plan task, count its modules and tests: p5 Task 7 (6 modules, 7 tests) could not fit 6 steps and 1 hour, so it was split 7a/7b/7c at card time, and a piece only a later task uses (`Net.SlideTip`) moved there (2026-11-10).
- When a card adds about 100 lines to a file near its line stop, count first and plan the module split on the card (p5t7a: WorldIndex hit 692 of 680, needed a Step 3b, 2026-11-10).
- A test card's `toThrow()` with no message can pass for the wrong reason (a nil index): name the assert's message (p5t6, 2026-11-10).
- `script_grep` patterns with parentheses match nothing: a card's sync check greps a plain unique substring (p5t7a 3b lost a Studio call, 2026-11-10).
- Size a card by turns too: one builder has 40 turns, so a card over about 3 code steps splits between two builders with a step note between them (p5t7a builder hit 40 mid Step 3, 2026-11-10).
- Count the spec file too: a card that adds 5 tests with a rig adds about 170 lines; if that crosses the stop, plan a new `<Name><Topic>.spec` plus a `<Name>Rig.luau` helper on the card (p5t7b Grab.spec hit 945, 2026-11-10). Budget 3 fetch pages for a narrow run over 3 spec files.
- An Edit job that `require`s game modules gets Edit's old cached copy (p5t7b today-slots: `Config` had no `Slots`). A check of new module code runs on the Server in Play, or inside a test run (2026-11-10).
- Progress index counts drift: recount from every `docs/progress/v2/*.md` (task rows minus removed or dropped) at each close, not by adding 1 (2026-11-10: index said 117 of 214, files gave 131 of 221).
- A "Stands on" check reads the code paths the placed things wake up, not only the listed tasks: p5 Task 12 places Epic and Legendary nests, but `ServerStorage.Assets.Eggs` has only 3 templates and `SpotModels.show` indexes `templates[rank]`, so plan 4 Task 2 (Epic and Legendary eggs) must come first. Card stopped, 2026-11-10.
- A plan's "reach walk: Task N's walks (passed)" can name walks that never covered the leg: 17b named 15e's cuff walks, which started on the strap. Open the walk's result file and check its start spot before copying the line (p5t17, 2026-11-10).
- The plan check passes a task written as a bold line with no "Stands on:" (plan 4 Tasks 3 to 13, 2026-11-10). Read each task block by eye. A big task card fits 800 words only with its tables in a sibling file without "card" in its name (`p5t12-tables.md`).
- Run-card pass line for the standing red: "1 failed: `the stuck scan on the real world the walk area passes the walk-area check` (its message names the problem count, which may change)". It is 1 test, not N failures in WalkAreaCheck.spec (p5t21 card said "5 failed", 2026-11-10).
