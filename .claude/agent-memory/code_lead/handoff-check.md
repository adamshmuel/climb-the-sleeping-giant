# Handoff check (`scripts/job-check.sh`)

- Don't start a test name with "picks the": `job-check.sh` reads it as picking a part by name. Name tests by where the player ends up ("lands on the safe spot").
- Write a later task's proof as "checked in Task N", never "proven in": `job-check.sh` reads "proven" as a start claim.
- Name `job-check.sh` only for job and world scripts. Spec files pass StyLua, selene and `luau-lsp analyze`, then their narrow run.
- A handoff names a spot's zone only from a `Zones.zoneAt` reading in the names-check call, never from the spec's wording.
- `job-check.sh --plan` reads only `#` headings, so a plan whose tasks are bold `**Task N:` lines passes with no "Stands on:" at all (V2 plans 3 and 6, 2026-11-04). Check bold task blocks by eye with grep.
- A full-run step line holding "Pass" fails job-check if it has a quote mark or the words line/scan/print: put test names on the next line, without "Pass" (Task 6a, 2026-11-04).
- job-check --handoff reads prose: "room"/"body fits" asks for StartCheck, the word "Play" asks for a session hold; name `PathCheck.roomToStand` and avoid "Play" in non-Play cards.
- job-check --handoff treats a heading that says "Step N" (even in brackets) as a step needing its own Stands on; refer to old steps by what they did ("the trial").
- job-check: "nearest" in a card reads as an unnamed pick; a full-run pass line may name only spec files that already exist.
- job-check --handoff also job-checks every named job file: reused snippets need held(), CHECK_ONLY, StyLua and a clean type check; a card stays under 800 words (hook). Run `job-check.sh <file>` on each reused snippet first (6a3 route card, 2026-11-04).
- An existing snippet a card edits is job-checked (held(), dry run in Edit); a snippet still to write passes on "written in Step N". To change a checked snippet without failing, have the builder write a new copy (6a3 let-go card, 2026-11-04).
- A card with new snippets plus Play steps passes 800 words: put snippet specs and miss labels in a sibling `work/<task>/<name>-scripts.md` (no "card" in the name). A later Play step on a fresh builder can reuse a running Play to save start, hold and trace pastes (6a3c, 2026-11-04).
- A sync check on a test file uses `script_grep`, never `script_read`: dotted `.spec` names fail (`rojo.md`). A world change's narrow run lists every spec that names the changed parts, not only the one the task is about (5b1: SunkParts alone missed 3 WaysUp reds, 2026-11-04).
- Narrow-run `FILTER` is a plain-text match on the spec module name: no "|" and no folder paths; budget 3 calls per spec, and leave read-only specs to the full run (5b2, 2026-11-04).
- A full-run pass line may hold no double quotes and none of "line", "scan", "print", and no CamelCase word that isn't a spec name (`RoutePoint_` fails): name failing tests as plain words after a colon. A Stands on line that says "before Step 1" counts as standing on Step 1 (6b, 2026-11-04).
- Any word "Play" in a card (even a split-off note) asks for the session hold: write "walk-offs" in non-Play cards (p5t15).
- `--handoff` reads "open" anywhere on a Stands on line (e.g. "planks open") as not final, and any heading with "Step N" in it as a step; write "still reached" and keep step names out of other headings (p5t15d).
- `--handoff` fails a line that picks "the spot nearest" with no path or position, and every job file needs "(no hold: Edit only)" in its first 5 lines unless it holds the session; put measured positions on their own line (p5t15d, 2026-11-09).
- A job never requires a test-side module that requires JestGlobals (WalkAreaFacts, RealWorld/Helpers): it errors outside Jest. Copy the needed function into its own job file that stores it in `shared`, pasted first; `--handoff` checks every named job alone, so joined parts that share locals fail it (p5t15d, 2026-11-09).
- A step heading with the word "Play" (even "Write the Play job files") needs a dry start; every Play step must start with one (group D in the job). Step headings also need the model name, even "resume Step N's builder".
- A "can a kid see X" shot needs an Edit sight-line ray check first (eye and phone camera to each target); never pick the spot from old walk starts (p5t16 see check failed twice: seam below the belly rim).
- Sum a card's minutes against the task's plan time before writing steps; phone = shots only, never walks; before shots go in the build step as builder calls (p5t16 grew to 73 of 60 min).
- `--plan` rejects waiting/open/pending words on a Stands on line, even inside a name ("Waiting..."): reword (p5t16, 2026-11-09).
- A Play card that avoids the word "Play" skips the Play-script checks (hold, CHECK_ONLY, dry run in Edit); 15d Step 2 ran that way. Write "Play" and pass them; reused sources go to `-<step>` copies "written in Step N" (p5t15d, 2026-11-09).
- Re-measure an accepted red's count before a card quotes it: a later world move changes it (p3t7: plan said 4 misses, real 2). A "same as before" test needs plain values read before the change, never a live read (p3t7 test 4).
- Before ruling any zone-box cut or removal, diff old vs new zone on a 1-stud grid over the whole giant in Edit (boxes in memory, no world change). p3t7 cut by sample points only; 3 rounds and ~60 Meadow holes followed.
- A card's "tests a world change touches" list = grep the tests for every changed part's NAME and for the folder's whole-list reads (`loadZones`/`readZones` + a count `#boxes`). p3t7 missed PillowFit's pinned ZONE_BOXES list.
- `--handoff` reads "builder" in a card's title as "build": a title with ladder/ramp/way up then asks for a reach walk. A code-only card's title avoids those words (p3t8b, 2026-11-10).
- `--handoff` reads "Step N" in a Stands-on line as the card's own Step N: name earlier work by its note file ("the route as built, 8c-step4-note.md"), not "8c Step 4" (p3t8c 4b, 2026-11-10).
- `--handoff` fails a job file named before it exists: write "(written in Step N)" on every line that names it. A full-run pass line names only spec files and counts, never a test's title (p3t8d, 2026-11-10).
- A shots-only Play step still needs "Dry run in Edit", a dry start, "Paste lines" and "Game signals", or `--handoff` fails 61a. Price a look task from where the value lives first: a world-held value adds a test, a world run and two shot sessions (p3t8e: 25 min became 50).
- A look task on a HUD-adjacent world sign opens with a read-only screen-pixel measure (projected points vs the HUD frame's AbsolutePosition), never trial shots by eye; and a passing test that disagrees with a failing shot is traced first (p3t8e step back, 2026-11-10).
- `--handoff` checks every `work/...luau` it names alone, so a split job's part A fails lint (b's names unused). Name split parts without the `work/` prefix and cite the `--joined` pass; a job that grows past 300 lines is split a/b from the start (p3t8e rerun, 2026-11-10).
- Shell edits to `.claude/` files are blocked on purpose. Edit memory and setup files only with the Edit or Write tools; never route around the hook with a python file or any other shell write (main chat correction, p3t8e, 2026-11-10).
- The word "proven" on a line with a "start" makes `--handoff` ask for "held 0.19 in <task> dry start"; a test-run start needs neither, so leave "proven" off that line (p3t8f card, 2026-11-10).
- A screen-measure job: screen y = AbsolutePosition.Y + the frame shift, read from a throwaway full-screen gui (IgnoreGuiInset, ScreenInsets None) as -AbsolutePosition.Y (58 computer, 78 phone simulator; GetGuiInset says 58 on both, wrong on the phone), read the real TextLabel inside any CanvasGroup, turn by AbsoluteRotation, and self-check one known spot (meter top) before judging. A unit test of a turned letter must turn it too: the unturned test passed while the lean broke the top gap (p3t8f, 2026-11-10).
- Step headings: "builder" reads as "build", and a module name like `NestPop` holds "nest", so the pair asks for a reach walk; name agents by letter only (G, H). An attribute name like `Waiting` on a Stands on line fails as not final (p5t8, 2026-11-10).
